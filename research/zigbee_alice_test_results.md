**Вывод фазы 1: ВАРИАНТ A подтверждён.** Один node C6 = 4 независимые именуемые лампы с диммером
+ группа. Прямой Zigbee-путь жизнеспособен. Осталось: голос (T1.5), reboot/rejoin (T1.6).

### Реверс протокола (из лога 0820_0305, 641 строк; только кластеры Level 0x0008 + OnOff 0x0006)

- **Шкала Level = ZCL 0..254** (плюс 255 на «просто включи»); 254/255 → duty max. Наш маппинг
  `level/254`, gamma 1.9, MIN_DUTY 20 — верный.
- **Последовательность ВКЛ:** `Level=0` → `OnOff=1` → `Level=<target>` (три записи ~100мс).
- **Последовательность ВЫКЛ:** `Level=0` → `OnOff=0`.
- **Яркость приходит ПОТОКОМ дискретных записей CurrentLevel**, а не одной командой с transition:
  голос/move — грубые шаги ~15 ед. каждые ~100мс; медленный слайдер — мелкие 2-5 ед. каждые ~30мс.
- **Группа «Фара» = 4 отдельных потока команд per-EP**, разнесённых на ~30мс (не один групповой
  адрес). Работает, но x4 трафика.
- **Причина «резкого 100% и ступенек»** (наблюдение Саши, поющий БП): ТЕСТОВЫЙ скетч применяет
  каждый Level мгновенно (`ledcWrite` из колбэка, soft-start намеренно НЕ включён). Инраш →
  БП звучит; поток грубых шагов Алисы виден как ступени. **Фикс:** в продуктовой прошивке
  `channels::write` уже делает slew к target каждый loop — он сгладит и ступени Алисы, и резкий
  вкл. Тест это не использует. Валидация — портировать slew в тест (см. журнал решений).

**Естественность голоса (детализация T1.5).** Отметить по каждой фразе ✅/⚠️/❌:

Наблюдения из лога действий:
- Яндекс поллит `query` состояния ~каждые 10 c пока карточка открыта -> Фаза 2: query ТОЛЬКО из
  кэша, никогда синхронный MQTT round-trip (проектное решение подтверждено).
- Есть призрачные дубли устройств (id a039d260/6cd0131d/5d651925) от прошлых попыток связки:
  их action обрывается на "scenario directives was handled" без провайдера/DONE. Источник кривого
  имени «Осветительный прибор» и мимо-цели `color_setting`. Фикс: удалить дубли в приложении.

**Важное правило:** имя из discovery Яндекс берёт только при ПЕРВОМ добавлении устройства;
дальше выигрывает имя из приложения. Программные имена = дефолты при первом добавлении
(решает «4x Лампочка»), не форс-override. Отсюда «Стоп-сигнал» показался дефолтным
«Осветительный прибор» (кэш прежнего имени) — фикс: переименовать карточку в приложении.

**Вывод: облачный путь даёт ровно то, чего не гарантировали Zigbee/Matter — программные имена
при первом добавлении + авто-группировку в «Фару».** Дальше Фаза 2: MQTT + ESP32.
