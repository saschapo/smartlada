# SmartLada Rev C - план тестирования

Прошивка **1.1.0-revC**. Документ для многодневного прогона: проходить сверху вниз,
отмечать результат прямо здесь (`OK` / `FAIL` + короткая заметка).
Незакрытые места и уже известные ловушки - в `SESSION_HANDOFF.md`.

## 0. Подготовка

Нужно: блок питания USB-C **PD с 12 В**, кабель USB к компьютеру (для логов и заливки),
телефон с приложением Яндекса, Wi-Fi-сеть 2.4 ГГц.

```
FQBN="esp32:esp32:esp32c6:ZigbeeMode=ed,PartitionScheme=zigbee_8MB,CDCOnBoot=cdc,FlashSize=16M"
arduino-cli compile -b "$FQBN" --build-path /tmp/smartlada SmartLadaRevC
arduino-cli upload  -b "$FQBN" -p /dev/cu.usbmodem101 --input-dir /tmp/smartlada SmartLadaRevC
```

**Три ловушки, которые исказят результат, если про них забыть:**

1. **Открытие USB-порта перезагружает плату** (`rst USB` в загрузочной строке). Любой запуск
   монитора = ребут. Во время BLE-сессии смотреть лог нельзя вообще: открытие порта выбьет
   плату из режима обновления.
2. **BLE OTA заливать только на PD 12 В.** На USB 5 В скорость падает до ~6.5 КБ/с и передача
   срывается на трети.
3. **Лампы не горят без 12 В** - это не поломка, а гейтинг. Для проверки логики на 5 В есть
   Settings -> Force Out.

Настройки сохраняются **через 4 секунды после того, как перестали меняться**. Если обесточить
раньше - изменения не переживут перезагрузку, и это ожидаемо.

## 1. Питание и загрузка

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| P1 | Подать 12 В PD | Сплэш, затем плавный разгон ламп ~1.5 с (не рывок) |
| P2 | Подать только USB 5 В | Лампы не горят, на экране покоя "NO 12V" |
| P3 | На 5 В: Settings -> Force Out -> Yes | Каналы открываются (видно по индикаторным LED) |
| P4 | Ребут после Force Out | Force Out сброшен, лампы снова заперты |
| P5 | Выдернуть 12 В при горящих лампах | Гашение **мгновенное**, не плавное |
| P6 | Вернуть 12 В | Плавный подъём с нуля через soft start |
| P7 | Statistics: VBUS, temp, rst, счётчик загрузок | Значения правдоподобны, счётчик растёт при ребутах |
| P8 | Statistics: маркер обхода | Показано `fix`. `NOFIX` = обход не установился, это дефект |

## 2. Локальное меню

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| M1 | Пройти все экраны туда-обратно | Нет зависаний, кнопка "назад" всегда возвращает |
| M2 | Timings у Chase (5 параметров) | Список листается, стрелки у края, окно едет за строку до края |
| M3 | Timings: дойти до низа и вернуться вверх | Экран стоит, пока курсор не дойдёт до верхней видимой строки |
| M4 | Параметр `Random`: нажать OK | Мгновенно `On` <-> `Off`, редактор не открывается, полоски нет |
| M5 | Удерживать UP на числовом параметре | Ускорение шага, значение не выходит за границы |
| M6 | `Reset To Defaults` в Timings | Параметры текущего эффекта вернулись к заводским |
| M7 | Поменять яркость, подождать 5 с, обесточить, включить | Значение восстановилось |
| M8 | Поменять яркость и обесточить **сразу** | Значение НЕ восстановилось (ожидаемо, см. п.0) |
| M9 | Дисплей: dim и off по таймауту, пробуждение кнопкой | Работает, лампы при этом не мигают |

## 3. Эффекты

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| E1 | Turn | Мигает только поворотник, фронты **с плавным нарастанием** (не 0-100-0) |
| E2 | Breathe | Все четыре канала дышат синхронно |
| E3 | Fade | Перелив по кругу без провалов |
| E4 | Drive | Сценарии сменяются, выглядит осмысленно |
| E5 | Chase, дефолт | Волна течёт, лампы перекрываются (огибающая 0.8 с длиннее шага 0.3 с) |
| E6 | Chase: `Fade Out` = 2 с, `Step` = 0.2 с | Лампа реально тлеет 2 с; одновременно горят несколько |
| E7 | Chase: `Step` больше суммы `Fade In + On + Fade Out` | Отдельные вспышки с паузами, без наложения |
| E8 | Chase: `On` = 1-2 с | Между разгоранием и гашением есть полка |
| E9 | Chase: `Random: On` | Лампы вразнобой, одна и та же не повторяется подряд |
| E10 | Смена эффекта во время удержания UP в Timings | Правка отменяется, чужой параметр не меняется |
| E11 | Менять `Soft Start` в Lamp Setup при работающем эффекте | Меняется плавность фронтов; при больших значениях быстрые эффекты мажутся - это ожидаемо |

## 4. Zigbee и Алиса

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| Z1 | Вкл/выкл каждой лампы из приложения | Гаснет/зажигается только она |
| Z2 | "Яркость поворотника 50%" | Меняется только поворотник |
| Z3 | Диммирование группы "Фара" | Все включённые лампы плавно, **выключенные не зажигаются** |
| Z4 | EP14: выбрать цвет | Выбирается эффект, на OLED виден новый режим |
| Z5 | EP14: белый | Эффекты выключаются, статический свет остаётся, поканальные яркости **не меняются** |
| Z6 | EP14: выключить | То же, что белый |
| Z7 | EP14: ползунок яркости | Меняется яркость эффекта, лампы плавно (ступеньки в приложении - его темп доставки) |
| Z8 | **Регрессия цвета:** белый -> цвет, 5-6 раз подряд, разные цвета | Ни разу не прыгает в красный, безымянный белый не появляется |
| Z9 | То же после перезагрузки платы, не трогая цвет | Пресет не подменяется (обход ставится до первой команды) |
| Z10 | Выставить разные яркости поканально, погонять цвет | Поканальные значения целы |
| Z11 | Менять яркость в меню платы | Плитки в приложении обновляются (дебаунс ~0.4 с) |
| Z12 | Выбрать эффект **в меню платы** | В приложении цвет НЕ меняется - так задумано, см. README |
| Z13 | Settings -> Zigbee: PAN, канал, LQI/RSSI | Значения правдоподобны |
| Z14 | Re-pair, затем заново привязать | Устройство поднимается, п. Z8 повторить после репаринга |

## 5. Радио: Zigbee или Wi-Fi

Одновременно они не работают - выяснено на железе: телефон не мог подключиться к точке,
пока поднят стек Zigbee. Радио отдаётся одному протоколу на загрузку.

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| R1 | Settings -> WiFi -> `WiFi` -> OK | Перезагрузка, Zigbee не стартует, поднимается точка |
| R2 | Экран Zigbee в режиме Wi-Fi | `stack off this boot / radio free for wifi` |
| R3 | Settings -> Zigbee -> `Zigbee` -> OK | Перезагрузка обратно, Wi-Fi гаснет, лампа снова в приложении |
| R4 | На веб-странице `SWITCH TO ZIGBEE` | Предупреждение, затем разрыв страницы и возврат в Zigbee |
| R5 | Снять и подать питание | Выбранный режим восстановился |

## 6. Wi-Fi и точка доступа

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| W1 | В логе строка `wifi: AP ...` | `up`, номер канала и адрес; `FAILED` - дефект |
| W2 | Экран WiFi | `setup AP`, имя `fara_NNNN`, ниже IP |
| W3 | `Show QR`, навести камеру | Телефон предлагает подключиться к сети платы |
| W4 | Подключиться, открыть любой адрес | Открывается страница (всё неизвестное отдаётся на неё) |
| W5 | `Show QR` ПОСЛЕ подключения телефона | QR сменился на адрес страницы |
| W6 | На странице сменить имя и пароль точки, SAVE | Точка перезапустилась с новым именем |
| W7 | Пароль короче 8 символов | Страница не даёт сохранить (WPA2 требует 8) |
| W8 | `WiFi Reset` на экране или на странице | Имя и пароль вернулись к заводским |
| W9 | Перезагрузка | Имя и пароль точки сохранились |

## 8. BLE OTA

Только с платой на **PD 12 В**.

| ID | Что делаем | Ожидаем |
|----|-----------|---------|
| O1 | Settings -> System -> Update Over BLE -> Yes | Ребут, экран режима обновления |
| O2 | Отпустить кнопку и нажать любую | Выход в обычный режим (удержанная с подтверждения не считается) |
| O3 | `uv run --with bleak python3 tools/ble_ota.py <bin>` | 1.1 МБ проходит за ~1 мин на 19-23 КБ/с, затем ребут в новую прошивку |
| O4 | Тот же прогон с `--drop-after-finish` | Плата всё равно коммитит и уходит в рабочую прошивку |
| O5 | Прервать клиента посреди передачи (Ctrl+C), затем повторить заливку | Вторая попытка проходит нормально |
| O6 | После обновления | Настройки и привязка к Zigbee целы (bonding в отдельном разделе) |

## Как фиксировать

Для каждого несовпадения нужны: **ID теста**, что именно увидел, и по возможности
загрузочная строка после сбоя (`[boot #N] reset=...`) - причина сброса теперь расшифровывается
полностью, и она сразу отделяет наш дефект от сброса со стороны хоста.

Лог с платы (помни: открытие порта её перезагрузит):

```
uv run --with pyserial python3 - <<'PY'
import serial, time
s = serial.Serial(); s.port='/dev/cu.usbmodem101'; s.baudrate=115200
s.dtr=False; s.rts=False; s.timeout=0.2; s.open()
t=time.time()
while time.time()-t < 120: print(s.read(4096).decode('utf-8','replace'), end='', flush=True)
PY
```
