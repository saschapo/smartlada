## 2. Земля под USB D+/D- (задача handoff)
- Пара `/USB_D+ /USB_D-` (U4->U1) и `Net-(J1-D+/-)` (J1->U4) — **вся по F.Cu**, 30 сегментов,
  **0 переходов на другой слой** => опорная земля = единый сплошной B.Cu-полигон на всём пути.
- B.Cu GND-заливка x[142..229.5] y[71.5..129.5] **полностью накрывает** маршрут пары
  x[177..214] y[78..96].
- **Длинный участок** (U4->U1, x186..214 @ y~94..95): под ним на B.Cu только GND, ближайшая
  не-GND медь (+3V3-перемычка @y=84.7) в ~10 мм. Возврат тока не разрезан.
- GND-стежок-via вдоль пары: @(177.9,81.4)(178.5,91.6)(194.7,79.0) + кластер у U1 (208..209).
- **Заметка (не блокер):** у разъёма/U4 (x171..180, y81..92) по B.Cu идут CC1/CC2 близко к вееру
  D+/D- — локальный «щелевой» участок земли в launch-зоне. Для ESP32-C6 (native USB = **Full-Speed
  12 Мбит**) некритично.

## 6. Финальный pin-map U1 (снят из нетлиста — ground truth для прошивки)
Каналы ламп (low-side, gate active-HIGH):
```
OUT0 = GPIO1   (/CH0_IN -> Rg1 -> Q1 -> /OUT0)
OUT1 = GPIO0   (/CH1_IN -> Rg2 -> Q2 -> /OUT1)
OUT2 = GPIO2   (/CH2_IN -> Rg3 -> Q3 -> /OUT2)
OUT3 = GPIO3   (/CH3_IN -> Rg4 -> Q4 -> /OUT3)
```
> IO0/IO1 перекрещены (IO1->OUT0, IO0->OUT1); IO2/IO3 прямые. Своп CH2/CH3 уже разрешён.

Питание/сенсоры:
```
CH224_PG   = GPIO10   (open-drain, active-LOW, 10k pull-up 3V3)
VBUS_sense = GPIO4    (ADC, делитель 100k/33k, 12В->2.98В)
```
Native USB: `D- = GPIO12`, `D+ = GPIO13`.
Strapping: `BOOT = GPIO9` (SW2), `RESET = EN` (SW1).
I2C (OLED, J4): `SCL = GPIO18`, `SDA = GPIO19`.
Кнопки (J4): `KEY1=GPIO23  KEY2=GPIO22  KEY3=GPIO21  KEY4=GPIO20`.
UART debug (J8): `TX = GPIO16`, `RX = GPIO17`.
Индик. LED: D2..D5 на /OUT0..3 (пассивные), D1 на +3V3, D6 на GND.

## Открытые заметки (не блокеры)
- VBUS-делитель 100k/33k: 2.98В при 12В — presence-sense надёжно, но у верхней (нелинейной)
  зоны ADC ESP32-C6. При входе >~13.3В ADC-пин уйдёт >3.3В (защиты нет). CH224K держит 12В =>
  риск низкий. Если нужна точность/запас — сделать 100k/24k (12В->2.32В).
- CC1/CC2 щель под launch-зоной D+/D- — ок для FS.
