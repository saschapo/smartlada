# Модуль 2.4" TFT (ST7789) + EC11 — рабочие заметки

Стендовый тест отдельного модуля: **2.4" SPI-дисплей ST7789 240x320** со встроенным
энкодером **EC11 (A/B/PUSH)** и отдельной кнопкой **K0**. Не связан с проектом
smartlada — самостоятельный скетч.

Проверено вживую на **ESP32-C6 dev-board** (навесной монтаж, питание 3V3),
2026-07-28. Всё работает. Скетч: [`Ec11Tft24Test.ino`](Ec11Tft24Test.ino).

---

## 1. Что за модуль (по схеме продавца)

| Узел | Факт | Следствие для кода |
|------|------|--------------------|
| Дисплей | ST7789, 240x320, **4-wire SPI, только запись** (MISO нет) | ID/регистры не читаются, offset/поворот подбираются вручную |
| `SDA/SCL` | Это **SPI** (SDA=MOSI, SCL=SCLK), НЕ I2C | не путать с I2C-шиной OLED |
| Энкодер A/B | 100R последоват., **10K подтяжка к VCC, 100nF на GND** (RC ~1 мс) | дебаунс уже на плате; `INPUT`, active-low, idle HIGH |
| PUSH | вал энкодера: R6 10K + C2 100nF, active-low | `INPUT`, доп. кондёров не надо |
| K0 (SW2) | R7 **10K подтяжка** + C3 100nF, кнопка на GND | подтяжка ЕСТЬ; `INPUT`, active-low |
| BLK (подсветка) | `BLK` -> 1K -> база **SS8050** (NPN), R3 10K вниз, low-side ключ | **active-HIGH**; плавающий/LOW = экран тёмный; PWM через LEDC работает |
| Питание | VCC 3.3/5V, логика 3.3 = VDDIO модуля | питаем от **3V3** |

> RC-дебаунс энкодера (~1 мс) впаян на модуле — выпаивать нечего. Он же не мешает
> быстрому кручению рукой (~10 об/с = ~5 мс/детент). Доп. конденсаторы A/B не нужны.

## 2. Распиновка (навесной монтаж на голый C6)

Обходим strapping (IO8/9/15), USB (IO12/13), BOOT. Если паять на эти пины — код
заработает без правок.

| Модуль | GPIO C6 | Роль |
|--------|---------|------|
| SCL (SCLK) | IO6 | SPI clock |
| SDA (MOSI) | IO7 | SPI data |
| CS | IO10 | chip select |
| DC (A0) | IO11 | data/command |
| RES | IO18 | reset |
| BLK | IO19 | подсветка, LEDC PWM, active-HIGH |
| A | IO2 | энкодер фаза A (PCNT) |
| B | IO3 | энкодер фаза B (PCNT) |
| PUSH | IO4 | кнопка вала, active-low |
| K0 | IO5 | отдельная кнопка, active-low |
| VCC | 3V3 | |
| GND | GND | |

Пины меняются в `#define` в начале `.ino`. SPI и PCNT на C6 роутятся через
GPIO-матрицу — пины можно любые (не только «дефолтные»).

## 3. Библиотеки

| Либа | Версия | Зачем |
|------|--------|-------|
| **GFX Library for Arduino** (moononournation) | 1.6.6 | дисплей: нативный C6, ест GFX-шрифты (совместимо с `bdf2gfx`) |
| **ESP32Encoder** (madhephaestus) | 0.12.0 | энкодер через аппаратный PCNT (новый IDF-драйвер, C6 ок) |

```bash
arduino-cli lib install "GFX Library for Arduino"
arduino-cli lib install "ESP32Encoder"
```

Почему не `TFT_eSPI`: на C6 (RISC-V) поддержка хрупкая, конфиг через `User_Setup.h`,
свой формат шрифтов. Arduino_GFX — надёжнее и совместим по шрифтам.

## 4. Инициализация (ключевые куски)

Дисплей — контроллер **настоящий ST7789**, цвета верные при **`ips=false`**
(INVOFF), поворот 1 (landscape 320x240), offset 0:

```cpp
Arduino_DataBus *bus = new Arduino_ESP32SPI(DC, CS, SCLK, MOSI, GFX_NOT_DEFINED);
Arduino_GFX *gfx = new Arduino_ST7789(bus, RES, /*rot*/1, /*ips*/false, 240, 320);
gfx->begin(40000000);   // 40 MHz стабильно на макетке
```

> Если бы попалась панель ILI9341 (частая подмена на 2.4"/240x320) — картинка была бы
> «каша»/со сдвигом. Тогда: `new Arduino_ILI9341(bus, RES, 1, false)`. Здесь — ST7789.

Энкодер — PCNT, full-quad даёт 4 отсчёта на детент (делим на 4). Внешние подтяжки
есть, внутренние не нужны. Порядок B,A задаёт направление (CW = increment):

```cpp
ESP32Encoder::useInternalWeakPullResistors = puType::none;
encoder.attachFullQuad(PIN_B, PIN_A);   // swap B<->A чтобы сменить направление
encoder.setFilter(1023);                // glitch-фильтр
long detents = encoder.getCount() / 4;
```

Подсветка — LEDC, active-HIGH; включать ДО первой отрисовки, иначе тёмный экран:

```cpp
ledcAttach(BLK, 20000, 8);   // 20 кГц, 8 бит
ledcWrite(BLK, 255);         // 0..255, диммирование без мерцания
```

## 5. Сборка и заливка

Собирать под **нативный USB-Serial-JTAG** (иначе Serial уходит в UART0):

```bash
arduino-cli compile --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc sketches/Ec11Tft24Test
arduino-cli upload  --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc -p /dev/cu.usbmodemXXXX sketches/Ec11Tft24Test
arduino-cli monitor -p /dev/cu.usbmodemXXXX -c baudrate=115200
```

Гочи (см. также bring-up RevB):
- По CDC загрузочные строки уходят до подключения монитора; `loop()` в простое молчит.
- `Serial.setTxTimeoutMs(0)` — чтобы `print` не блокировал `loop()`, если хост держит
  порт открытым, но не читает.

## 6. Результаты стенда (что реально намерено)

- **Контроллер ST7789** подтверждён: Border-тест — offset 0, обрезки нет.
- **Цвета** верные при `ips=false`.
- **Энкодер**: быстрое кручение без потерь шагов, реакция на дисплее мгновенная.
- **Подсветка**: диммирование LEDC 20 кГц — без мерцания на любой яркости.
- **Скорость SPI @ 40 МГц**:
  - полный кадр 240x320x16 (`fillScreen`): **~34 мс** (`fullFill=33825 us`)
    -> потолок **~29 fps** при полной перерисовке;
  - `fillRect 40x40`: ~720 us; лёгкий цикл (мелкий rect): ~690 loop/s.
- **TE-линии на разъёме НЕТ** -> vsync невозможен (как у OLED). Полноэкранная
  анимация даёт tearing + моргание.
- **Mura на белом** — от механического изгиба стекла на макетке; ушла после прогрева
  клеевого слоя (снялось напряжение). Панель не бракованная. **В корпусе не зажимать/
  не гнуть.**
- **80 МГц SPI** мерить только на плате с короткими дорожками; на dupont — артефакты
  по signal integrity, тест будет про провода, а не про панель.

## 7. Антифликер (важный вывод для будущего UI)

«Стереть `fillRect(BLACK)` -> нарисовать» без двойного буфера/TE виден как вспышка,
экран «рябит». Рабочие приёмы (применены в скетче):

1. **Текст поверх себя с непрозрачным фоном фиксированной ширины:**
   `gfx->setTextColor(fg, bg); gfx->printf("%6ld", v);` — новое затирает старое в тех
   же ячейках, без отдельной очистки -> без ряби.
2. **Обновлять только меняющуюся область** (dirty-rect), а не весь экран.
3. Для спрайтов/иконок — `drawBitmap(..., fg, bg)`: фон под нулевыми битами
   перекрывает предыдущий кадр без смаза.

Полноэкранных `fillScreen` в цикле анимации избегать.

## 8. Пиктограммы/анимация из `.h`

Формат `checkmark_ok_64_64_28f.h`: `frames[28][512]` в PROGMEM — **64x64 1bpp**,
MSB-first (стандартный формат `drawBitmap`), 512 байт/кадр = 64*64/8. (В файле есть
неиспользуемая `static int ..._frame` — можно игнорировать.)

Отрисовка кадра маской (зелёным на чёрном), без смаза:

```cpp
gfx->drawBitmap(x, y, checkmark_ok_64_64_28f_frames[i], 64, 64, GREEN, BLACK);
```

Проигрывание — в режиме `Anim OK` (`updateAnim()`): автопрокрутка 28 кадров, холд
на последнем, энкодер = скорость (10..200 мс/кадр).

**Конвертер** `tools/anim2h.py` (Pillow): GIF/APNG/папка-PNG -> .h.
- `--format 1bpp` (маска, `drawBitmap`, одноцветная иконка) или
  `--format rgb565` (цвет, `draw16bitRGBBitmap`, в разы больше flash).
- `--size 64 --frames 28 --threshold --alpha auto|on|off --invert --out ...`.
- Видео (mp4/mov) требует ffmpeg (нет в системе) — экспортируй в GIF.
Пример цветной анимации в скетче: режим `Earth` (`earth_64_64_24f.h`, RGB565 24f)
из примера GFX ezgif-resize; ~192 КБ flash на 64x64x24.

**Масштабирование** (drawBitmap не умеет): собрать RGB565-буфер NxN нужного размера
nearest-neighbor из битов и вывести одним трансфером — быстро и без ряби:

```cpp
gfx->draw16bitRGBBitmap(x, y, scaledBuf, SW, SH);
```

## 9. Режимы теста

`Info -> Colors -> Bars+Gradient -> Border -> Encoder -> Buttons -> Bench ->
Backlight -> Anim OK` (по кругу).

Навигация: **PUSH коротко = следующий, K0 коротко = предыдущий, K0 удержание =
сброс счётчиков.** Энкодер активен в `Encoder` (значение), `Backlight` (яркость),
`Anim OK` (скорость).

| Режим | Что проверяет |
|-------|---------------|
| Info | распиновка, контроллер, подсказки |
| Colors | инверсия, битые пиксели, mura, RGB-порядок |
| Bars+Gradient | цветовые полосы, banding 16 бит |
| Border | offset/обрезка краёв (рамка 1px + уголки) |
| Encoder | PCNT: направление, потери шагов, детент/с, dirty-rect отклик |
| Buttons | PUSH и K0 раздельно, счётчики, long-press |
| Bench | время full/partial заливки, fps, tearing (движущийся квадрат) |
| Backlight | PWM-диммирование, минимум без мерцания |
| Anim OK | проигрывание 64x64 1bpp анимации из .h |
